# Code navigation

Use source files as the authority. Serena is the symbol and reference navigator; Graphify is the cross-file code graph.

## Choose a route

| Question | Start with |
| --- | --- |
| Find a definition, callers, implementations, or a file outline | Serena: `find_symbol`, `find_referencing_symbols`, `find_implementations`, `get_symbols_overview` |
| Trace a path across modules or inspect graph neighbors | Graphify: `query_graph`, `shortest_path`, `get_neighbors` |
| Verify current behavior or edit code | Read the referenced source and tests |

Pass Serena a `relative_path` when the search area is known. Use `docs/agents/domain.md` and `CONTEXT.md` for domain language; they do not describe the current implementation.

## Current flow map

- **Renderer requests:** request helpers in [frontend IPC](../../src/frontend/IPC/main.ts) cross the [preload bridge](../../src/electron/preload.ts) to [Electron IPC](../../src/electron/IPC/main.ts) and [response handlers](../../src/electron/IPC/responsesMain.ts). The tagged request API distinguishes success, timeout, cancellation, and handler error; legacy wrappers keep their older return shapes. Shared contracts are in [Request.ts](../../src/types/IPC/Request.ts), [Channels.ts](../../src/types/Channels.ts), [Main.ts](../../src/types/IPC/Main.ts), and [ToMain.ts](../../src/types/IPC/ToMain.ts). See `scripts/tests/ipc-request.test.mjs` and IPC request tests beside the main-process helpers.
- **Presentation Output state and playback:** [MainOutput.svelte](../../src/frontend/MainOutput.svelte) mounts the ordinary DOM [Output.svelte](../../src/frontend/components/output/Output.svelte). The custom Pixi/WebGPU renderer, renderer-specific settings, and playback integrations have been removed; normal Electron GPU acceleration remains. Publishers feed [OutputStateBroker](../../src/electron/output/OutputStateBroker.ts); [OutputStateClient](../../src/frontend/outputState/OutputStateClient.ts) serializes topic application and keeps the latest pending revision. [dependencyGate](../../src/common/outputState/dependencyGate.ts) applies only snapshots with exact dependencies. READY manifests, missing-state requests, apply/ack, retries, output recreation, and health reporting live in the broker/client path and `scripts/tests/output-state-*.test.mjs`.
- **Video controls and observations:** [MediaControls.svelte](../../src/frontend/components/output/tools/MediaControls.svelte) and [public API actions](../../src/frontend/components/actions/apiHelper.ts) route through [VideoPlayer](../../src/frontend/components/media/video/videoPlayer.ts) and its identity-aware [outputPlaybackControl](../../src/frontend/components/media/video/outputPlaybackControl.ts). A selected timeline audio item keeps its existing audio owner. Shared background playback targets only linked outputs that still show that identity; a per-output fallback is allowed only while the requested output still shows it. The entry and visible background are rechecked before each command, so a delayed control cannot act on a replaced entry. Background commands use the existing `OUTPUT` `DATA`/`TIME` messages tagged with media identity. The displayed video path in [BackgroundMedia.svelte](../../src/frontend/components/output/layers/BackgroundMedia.svelte) and [Video.svelte](../../src/frontend/components/media/Video.svelte) publishes native playback observations to the canonical [playback store](../../src/frontend/outputState/playbackStore.ts) and [state reducer](../../src/frontend/outputState/playbackState.ts). Controls and mirrored previews subscribe to observations and use [preview sync rules](../../src/frontend/components/output/videoPreviewSync.ts); they do not send observations back as commands. Legacy `MAIN_DATA`/`MAIN_TIME` updates continue to synchronize rendered media, with stale media identities and retired playback sources filtered. See `scripts/tests/video-player-playback-control.test.ts`, `config/testing/output-playback-lifecycle.test.ts`, and `config/testing/output-preview-playback.test.ts`.
- **Media folder scans:** `READ_FOLDER` in [response handlers](../../src/electron/IPC/responsesMain.ts) calls [file scanning](../../src/electron/utils/files.ts), then [IndexerService](../../src/electron/indexer/IndexerService.ts) and its [worker](../../src/electron/indexer/worker.ts) / [DirWalker](../../src/electron/indexer/DirWalker.ts), with an in-process fallback before any batch is delivered. Scans allow two active and two queued jobs; each scan streams batches of up to 200 entries, with up to 16 concurrent stats and an acknowledgement before the worker sends the next batch. Cancellation crosses IPC and worker boundaries. The UI accumulates batches and the final reply reports completion/count rather than returning a second full map. [Media.svelte](../../src/frontend/components/drawer/media/Media.svelte) handles display and recovery states; `scripts/tests/media-folder-scan.test.mjs` covers this flow. Show loading remains separate in [shows.ts](../../src/electron/utils/shows.ts).
- **Remote and production paths:** [servers.ts](../../src/electron/servers.ts) registers the HTTP apps; each app has its own `src/server/<app>/main.ts` entry. Capture routing starts in [CaptureHelper](../../src/electron/capture/CaptureHelper.ts), with lifecycle and transmission in `src/electron/capture/helpers/` and [distribution compatibility notes](../testing/distribution-compatibility.md). Code-path tests do not establish physical-device or hardware qualification; those checks remain pending in the [output acceptance checklist](../testing/output-acceptance.md).

This is a bounded map of the current checkout, not a claim that every runtime or hardware path has been exercised. See the [validation record](../testing/foundation-validation.md) for the current automated evidence and baseline limits. Manual hardware qualification remains pending in the [output acceptance checklist](../testing/output-acceptance.md) and [distribution compatibility matrix](../testing/distribution-compatibility.md).

For the planning baseline and implementation tickets, see the [Presentation IPC foundation spec](https://github.com/ccfii-engineering/ccfii-free-show/issues/45) and issues [#46](https://github.com/ccfii-engineering/ccfii-free-show/issues/46)–[#51](https://github.com/ccfii-engineering/ccfii-free-show/issues/51). The remote PowerPoint blank-preview fix ([#52](https://github.com/ccfii-engineering/ccfii-free-show/issues/52)) is implemented and browser-regression tested, pending release. Layout behavior ([#53](https://github.com/ccfii-engineering/ccfii-free-show/issues/53)) remains deferred and unreproduced.

## Set up and refresh

Run `scripts/navigation/setup-code-navigation.sh` to install the pinned Serena and Graphify runtimes into the ignored `.cache/code-navigation/` directory and initialize Serena's project files. The checked-in [Serena project config](../../.serena/project.yml) enables Svelte and TypeScript; its language servers initialize when Serena starts. The first symbol lookup may need to warm its language-server cache.

Run `scripts/navigation/update-code-graph.sh` after tracked code changes. It makes a fresh Graphify 0.8.31 AST graph in an isolated staging tree, using exactly the tracked files Graphify classifies as code. Documents, media, ignored files, and untracked files are excluded; the fingerprint covers exactly those code inputs. This prevents stale nodes from surviving a rename or deletion. The ignored `graphify-out/` contains `graph.json` and matching freshness metadata. No automatic hooks run. Graphify checks the graph file on each MCP request and reloads it after a refresh; reconnect the MCP server if a client continues to show stale results.

The project MCP entries are in [`.mcp.json`](../../.mcp.json) for Claude Code and [`.codex/config.toml`](../../.codex/config.toml) for Codex. Restart the client after setup so it loads those entries. Codex loads project MCP configuration only for trusted workspaces; trust this checkout if it prompts.
